SQLite treats NULL as distinct from any other value (including NULL), so a UNIQUE over `(..., game_id, window_start, window_end)` does NOT fire if any of those three is NULL. My first test had two scope='game' rows with NULL window bounds — it passed silently. Fix: fill all eight UNIQUE-key columns on the collision row (mix scope + game_id + window_start + window_end), or assert the auto-index exists via `sqlite_master WHERE type='index' AND tbl_name='detector_runs' AND sql IS NULL` (the auto-index has sql=null because it's implicit).

If future schema migrations land (0002-…), the runner will need a `schema_migrations` ledger; out of scope for US-005.
  - **better-sqlite3 file-resolution under tsx + ESM.** `dirname(fileURLToPath(import.meta.url))` resolves to the source dir (`packages/db/src/cache-migrations/`) under both tsx-direct execution and vitest. If a future task ever introduces a build step that copies dist/, the .sql file will need to be copied alongside (e.g. tsup `loader: { ".sql": "file" }` or an explicit cp step).
  - **PRAGMA foreign_keys is OFF by default in SQLite.** The migration's `ON DELETE CASCADE` is inert unless `PRAGMA foreign_keys = ON` is set on the handle. `openCacheDb()` sets it; the cascade test sets it manually after `new Database(":memory:")`.   - **Don't use arrow-shorthand `() => voidFn()` in vitest `expect(...).toThrow()` blocks.** The `no-confusing-void-expression` rule rejects it; wrap in braces: `expect(() => { voidFn(); }).toThrow()`. Hit this on the idempotence test (`runMigrations` returns void).

- **Learnings for future iterations:**
  - **AC says "exits non-zero when any plan contains the substring 'SCAN' on a non-trivial table ... without an associated USING INDEX".** Implementation: for each plan row, split on whitespace after "SCAN " and look up the first token in a per-query `aliases` map (alias -> physical table). If `aliases[token] ?? token` is in NON_TRIVIAL_TABLES, and the row does NOT contain "USING ", flag. This handles both `SCAN qt` (aliased) and `SCAN market_microstructure_events` (bare). For the games-last-24h query, `SCAN g` resolves to `games` which is intentionally not in NON_TRIVIAL_TABLES (small lookup table) — correct no-flag behavior. If a future query introduces a new physical table that should be index-backed, add it to NON_TRIVIAL_TABLES.
  - **`Database` type isn't visible from scripts/tsconfig.json.** @types/better-sqlite3 is a devDep of packages/db, not the repo root. `import Database from "better-sqlite3"` resolves at runtime via pnpm hoisting (so tsx + open.ts work fine), but typescript-eslint inside scripts/ can't see the type. Use `type GoldDbHandle = ReturnType<typeof openGoldDb>` instead — avoids both the unsafe-member errors AND a redundant better-sqlite3 import in the script. Pattern applies to any future scripts/ helper that needs to take a DB handle parameter.
  - **`EXPLAIN QUERY PLAN` rows are returned as `unknown[]`** by better-sqlite3's `.all()` under strict TS. The shape is `{id: number, parent: number, notused: number, detail: string}`. Hand-validate with `asPlanRow(v): PlanRow` — assignment-only narrowing via `in` operator + `typeof` checks, no `as` cast. Same pattern as extract-fixtures.ts. The `notused` column exists but is not part of the plan tree; ignore it.
  - **Plan-tree rendering uses depth-by-parent.** Each row's depth is `depthById.get(row.parent) + 1`, with `parent === 0` mapped to depth=0 (root). 2-space indentation per depth. Format header is just "QUERY PLAN" (matches sqlite3 CLI), and lines after that are the indented `detail` strings. No box-drawing — pure indent keeps diffs cheap to read and immune to terminal-width drift. If a future story wants the sqlite3 CLI's `|--` / `` `-- `` box-drawing, the algorithm is "for each row, walk parent ancestors, emit `|  ` for each non-last-child ancestor and `   ` for last-child ancestors, then `|--` for non-last sibling and `` `-- `` for last sibling" — but the simpler indent format has held up fine for snapshots so far.
  - **Plain-text `.plan.txt` snapshots are NOT prettier-formatted.** prettier-3 + `--ignore-unknown` skips them by extension. No `.prettierignore` entry needed. If a future story wants them formatted (or pretty-printed JSON), pick the file extension carefully.
  - **Trailing newline on snapshot output.** `lines.join("\n") + "\n"` — the trailing newline matters: editors (and prettier) generally add a trailing newline on save; without it, perturbation tests that re-write the file via `sed -i.bak` may introduce a one-character diff that looks like real drift.
  - **Indexes the planner picked under SQLite 3.x (Phase 0 snapshot).** Worth knowing for future routes:
    - games (full SCAN, small table — fine)
    - game_states correlated subquery: `idx_game_states_game_captured` (game_id, captured_at DESC)
    - source_markets WHERE game_id: `idx_source_markets_game_instrument` (game_id, instrument_id, id) as COVERING — the planner prefers this 3-column index over the simpler `idx_source_markets_game_id` because all selected columns are present in the index. If future queries SELECT additional columns from source_markets, the planner may fall back to the table; watch for SCAN.
    - quote_ticks WHERE source_market_id AND captured_at: `idx_quote_ticks_unique_observation` (UNIQUE INDEX on (source_market_id, captured_at)) — sometimes also chosen over the dedicated `idx_quote_ticks_source_market_captured` because the UNIQUE index covers the equality+range exactly. Either is acceptable; the snapshot locks the choice.
    - market_microstructure_events WHERE game_id: `idx_market_microstructure_game_time` (game_id, event_timestamp DESC)
    - nba_play_by_play_actions WHERE game_id: `sqlite_autoindex_nba_play_by_play_actions_1` (the implicit index on the UNIQUE constraint `(game_id, action_number)`)
