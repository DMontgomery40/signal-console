- **Learnings for future iterations:**
  - **SQLite UNIQUE + NULL is the trap.** When you assert "INSERT duplicate row throws UNIQUE," every column in the UNIQUE tuple must be non-NULL on both rows. SQLite treats NULL as distinct from any other value (including NULL), so a UNIQUE over `(..., game_id, window_start, window_end)` does NOT fire if any of those three is NULL. My first test had two scope='game' rows with NULL window bounds — it passed silently. Fix: fill all eight UNIQUE-key columns on the collision row (mix scope + game_id + window_start + window_end), or assert the auto-index exists via `sqlite_master WHERE type='index' AND tbl_name='detector_runs' AND sql IS NULL` (the auto-index has sql=null because it's implicit).
  - **`CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS` is all you need for idempotence.** The migration runs to completion on the first call and is a no-op on subsequent calls — no version table needed at this stage. If future schema migrations land (0002-…), the runner will need a `schema_migrations` ledger; out of scope for US-005.
  - **better-sqlite3 file-resolution under tsx + ESM.** `dirname(fileURLToPath(import.meta.url))` resolves to the source dir (`packages/db/src/cache-migrations/`) under both tsx-direct execution and vitest. The 0001-init.sql sits next to runner.ts and is read at call time via `readFileSync(..., "utf8")`. This works because we never bundle/emit — `noEmit: true` + tsx run-from-source. If a future task ever introduces a build step that copies dist/, the .sql file will need to be copied alongside (e.g. tsup `loader: { ".sql": "file" }` or an explicit cp step).
  - **PRAGMA foreign_keys is OFF by default in SQLite.** The migration's `ON DELETE CASCADE` is inert unless `PRAGMA foreign_keys = ON` is set on the handle. `openCacheDb()` sets it; the cascade test sets it manually after `new Database(":memory:")`. Any future code that opens the cache DB outside `openCacheDb()` must also set this.
  - **Don't use arrow-shorthand `() => voidFn()` in vitest `expect(...).toThrow()` blocks.** The `no-confusing-void-expression` rule rejects it; wrap in braces: `expect(() => { voidFn(); }).toThrow()`. Hit this on the idempotence test (`runMigrations` returns void).
  - **`process.env.SQLITE_USE_URI = '1'` is mirrored in runner.ts** for the same reason it's in open.ts (per US-004 notes). The cache DB only opens plain paths so URI parsing doesn't matter for cache, but setting it here is cheap insurance against a process where runner.ts loads first and freezes the addon's URI mode to off — that would break the gold-DB open in the same process. If a future US-prefer to centralize, factor a tiny `packages/db/src/uri-mode.ts` side-effect module and import from both.
  - **`.pluck()` is the readable way to assert COUNT(\*) under `consistent-type-assertions: never`.** Returns `unknown`, but you can pass that directly to `expect(...).toBe(0)`. Avoids `as { count: number }` casts. Helper pattern in the test file: `const stmt = db.prepare("SELECT COUNT(*) FROM ..."); stmt.pluck(); expect(stmt.get()).toBe(N);` — repeatable for future cache/query tests.
  - **`Database.RunResult` is the typed return of `stmt.run(...)`.** `.lastInsertRowid` is `number | bigint`; wrap with `Number(...)` to use as a parameter to follow-up statements. Avoids `as number` casts.
