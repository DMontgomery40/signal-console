## Historical report notes about the algorithm

The user pointed out, with their hair on fire, that **the detector window is NOT derived from `games.scheduled_start`**. From the engineering appendix of `report.html`:

> "in-play window $[t_0,t_1]=[\min,\max]$ of NBA play-by-play `time_actual`; drop heartbeats, the 0.500 opening anchor, and quote gaps > 300 s; bin into 60-second buckets."

> Equal- and money-weighted bucket intensities:
> $$I^{\mathrm{eq}}_{b}=\sum_{i\in b}|\Delta p_i| \quad\quad I^{\mathrm{vw}}_{b}=\sum_{i\in b}|\Delta p_i|\,\ln(1+v_i)$$

> Fire condition: $I_b \ge \operatorname{median}(I_{b-W:b-1}) + K\cdot\operatorname{MAD}(I_{b-W:b-1})$ with $W=20$, 8-bucket warm-up.

**There is one detector. It produces one number per bucket.** The "combined detector" the user referenced is NOT board-mad ∪ off-price-print as if they were separate UI radios — it's that the **whole-board money-weighted intensity already combines every market's contribution**. The off-price-print signal is a complementary alarm in the desk's workflow, but they are not a switch in the backtest UI. **I (the previous agent) wrongly built the backtest UI to be one-detector-at-a-time, then got the user's frustration when they reasonably said "in real life it's always both."** Read the report yourself; don't take my word for what's "combined."

I also added a `scheduled_start ± [30 min, 3.5 h]` window fallback in both `apps/api/src/services/board.ts` and `apps/api/src/services/backtest.ts`. **This is contrary to the report.** The report says the window is PBP MIN..MAX of `time_actual`, full stop. My fallback should be reviewed — likely removed entirely, with the failure mode being "the game doesn't fire because we don't have PBP" rather than "we substitute scheduled_start and produce incorrect numbers." Discuss with the user before deciding.
